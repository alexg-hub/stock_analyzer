Stock Analyzer

A nightly screener that finds technical setups, grades the company behind each one, scores a 0-100 verdict, and then buys every signal on paper to measure which of those judgments actually predicted the return. Every number is computed in Python. Results arrive as one Discord message a night, and the whole system can be run from Claude through an MCP server.

How a night works

One process, run_scanners.py, runs every step in order and posts once. Each step is fail-safe: a failure costs its own section of the message, not the night.

Capabilities

The nightly pipeline, the tools you run on demand, and the measurement that grades both.

Technical screens

  • Breakout from a tight multi-month range on volume, with a strong green candle.
  • Pullback to a rising 150-day SMA after a year-long uptrend.
  • Reclaim of a long-term SMA after a long downtrend, gap-up aware.
  • Trend: the day a near-linear 10-month uptrend first qualifies.

Partial setups are alerted too, with the failing condition named.

Quality registry

  • ⭐ Badge: passes every quality gate (P/E, D/E, margins, ROIC, FCF…).
  • 🚫 Veto: visibly failing (Altman Z, Beneish M, going concern, restatement…). A label, never hidden.
  • Plane: separate reward and risk axes, quadrants buy / speculative / dull / avoid.
  • Sector-relative scoring against sector peers, so utilities are not penalized for being utilities.

Virtual portfolio

  • Buys every recorded signal; nothing is filtered out, so every attribute can be compared.
  • Double-top exit flags a position without closing it, so two exit methods can be compared.
  • analyze ranks which screen, rule, veto, verdict or research judgment predicted returns, using Benjamini–Hochberg q-values.

Risk/reward plane

  • Grades all 903 stocks (or the week's signals) on both axes.
  • Writes a table, a scatter chart and an interactive page, and rebuilds the sector peer distributions.
universe_scan.py

Industry valuation

  • Splits each industry's price move into multiple change and earnings change.
  • Flags cheap (multiple low while earnings grew) and rich (multiple high and expanding).
industry_valuation.py

Research and reports

  • Theme screen: companies that benefit from a dated real-world event, from news and SEC filings.
  • Enrich: qualitative research recorded as categories the portfolio can grade.
  • Dossier: one page per ticker with everything graded and researched.
  • Backtests per ticker and across the universe, plus a threshold tuner.

Where AI fits

The analyzer never runs a model; a test fails if any code path could start one.

Python decides

Every screen, gate, veto, score, tier, verdict sentence and portfolio statistic. Each figure can be traced to config.json and recomputed.

Claude researches, from a session

The enrich and theme-screen skills add qualitative research and name candidates. Their output is recorded beside the data, cannot carry a score, and is graded by the portfolio like any other hypothesis.

Optional integration: Interactive Brokers MCP

The two research skills can use the Interactive Brokers connector in Claude for company and theme data no free API offers. The nightly analyzer never needs it.

enrich skill: the moat graph

  • search_contracts resolves the ticker to its US contract.
  • get_company_connections gives products and revenue mix, ranked competitors and how they compete, and geography, each with evidence.
  • get_company_themes · get_theme_details give secular exposure and ranked peers.
  • get_option_data gives the implied move when a catalyst is near.

theme-screen skill: finding names

  • search_investment_topics → get_theme_details ranks companies by relevance to a theme. Query with short singular nouns: grid, semiconductor.
  • get_company_connections maps the supplier and competitor graph behind a name.
  • search_contracts confirms a US listing; foreign listings are refused when recorded.

Setup and limits

  • Connect Interactive Brokers under Connectors in Claude and sign in. If an enrich report's moat section comes back empty, the login has expired; renew it.
  • Without it, both skills still run on the analyzer's tools and web search, and the report says which sections are thin.
  • Research only. Account tools (get_account_*, get_pa_*) are never called, and holdings are never mentioned.

Managing it from Claude (MCP)

mcp_server.py exposes the whole system as tools. Long runs return a job_id immediately; poll it with job_status.

Claude Code

  1. Open Claude Code in the repo folder. .mcp.json is already there.
  2. Approve the stock_analyzer server once.
  3. Run /mcp to confirm it shows connected.

The skills (enrich, theme-screen, tune-thresholds, universe-backtest) load automatically.

Claude Desktop

Settings → Developer → Edit Config, add the server with absolute paths, then restart the app.

"stock_analyzer": {
  "command": "C:\\path\\to\\python.exe",
  "args": ["C:\\path\\to\\stock_analyzer\\mcp_server.py"],
  "env": { "PYTHONUTF8": "1" }
}

After editing code

The server keeps the code it started with. Run /mcp → reconnect (or restart Desktop). Check offline with python mcp_server.py --selftest.

Safe by default

A tool prompts if it can post to Discord, change config.json, or write into the signal table. Discord tools default to send=False; config writers preview a diff until confirm=True.

Tuning from a session

params_list("quality") shows every parameter, including disabled ones. config_set(path, value, confirm=True) changes one value, validates it, and backs up the file.

Reading results

Reports, logs and CSVs live under output/ and are read as ordinary files. There are no file-reading tools to maintain.

Where files go

output/history signals and verdicts · reports facts, charts, dossiers · portfolio ledger and findings · logs one line per step.

Configuration

Every threshold and label is in config.json. Secrets (Discord webhook, SEC contact) go in .env, never in config.

Checks

python tests/run_all.py, about 4 minutes, offline. Research and measurement only; not investment advice.
